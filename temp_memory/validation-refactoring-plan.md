## 問題点

1. **手動バリデーションとValidationPipeの重複**
   - 同じバリデーション処理が手動とデコレータで二重実装
   - メンテナンス負荷の増大

2. **エラーハンドリング方式の不統一**
   - 手動バリデーション: renderでエラー表示
   - ValidationPipe: 例外投げる→要ハンドリング

3. **コード可読性・保守性の低下**
   - バリデーション処理がコントローラーに散在
   - ビジネスロジックとバリデーション処理の混在

4. **開発効率の問題**
   - 前回の入稿機能実装時にValidationPipe使用せず原因調査に時間を要した
   - 新機能追加時の一貫性確保が困難
