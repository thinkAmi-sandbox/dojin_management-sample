## 🔍 今回発生した非効率な部分

### 問題点
1. **ファイル保存の問題**: 複数回「保存されていない」とのフィードバック
2. **段階的指示**: 本来1つのプロンプトで完了できる作業を複数に分割
3. **確認作業**: git statusでの保存確認が複数回必要

### 原因分析
- 最初のプロンプトが「計画してください」という分析指示で終わっていた
- 「保存してください」という明確な実行指示が分離されていた
- ファイル操作の具体的な指示が不足していた

### 教訓
- **具体的な成果物**: 「何を」「どこに」「どのように」保存するかを明確に
- **完結した指示**: 分析→実行→保存→コミットを1つのプロンプトに
- **TodoWrite活用**: 複雑なタスクでは進捗管理を含めた指示が効果的

## 🚀 最適化されたプロンプトテンプレート

```
【タスク】: @docs/system_design/01_event_exhibit.md を既存システムに統合する設計・実装計画の作成

【実行内容】:
1. 設計書分析と既存パターン調査（@docs/, @CLAUDE.md）
2. 統合計画の立案
3. 以下ファイルの作成・更新・保存：
   - @CLAUDE.md: データベース設計セクション更新
   - @docs/db/: 新テーブル設計書5つ作成
   - @docs/01_url.md: URL設計追加
   - @todo_memory/: 実装計画書作成
4. 全変更のコミット

【進捗管理】: TodoWriteで4つのタスクを管理
【最終確認】: git statusでclean状態を確認
```

## 📊 効率性の比較

| 項目 | 実際の実行 | 最適化版 |

| プロンプト数 | 8回 | 1回 |
| ファイル保存確認 | 5回 | 0回 |

- **手動確認削減**: 複数回の保存確認が不要
- **認知負荷軽減**: 一度の指示で完結

## 🎯 一般的なプロンプト設計原則

### 1. 完結性
- 分析・実行・保存・確認を1つのプロンプトに含める
- 「〜してください」で終わらず、「〜して保存してください」まで指定

### 2. 具体性
- 出力ファイルのパス・名前を明確に指定
- ファイル内容の構造・形式を既存パターンで示す

### 3. 進捗管理
- TodoWriteツールの活用を明示的に指示
- 段階的実行の流れを事前に定義

### 4. 検証可能性
- 最終状態の確認方法を含める（git status等）
- 成功条件を明確に定義
