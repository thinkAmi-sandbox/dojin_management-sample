# テストデータファクトリーシステム実装計画

## 📋 目標

現在の問題点（DRY原則違反、重複コード約260行、メンテナンス困難）を解決し、保守性・可読性・テストデータバリエーションを大幅に向上させる。

## 🔧 実装内容

### Phase 1: テストデータファクトリー基盤構築

#### 1. test/helpers/test-data-factory.ts作成
- 各エンティティのファクトリーメソッド実装
- デフォルト値 + オーバーライド可能な柔軟な設計
- 関連データ自動作成機能
- タイムスタンプ・ユニーク値自動生成

#### 2. 型安全な設計
- TypeScript型定義活用
- エンティティ型から自動推論
- オプショナル・必須フィールドの適切な処理

### Phase 2: 関連データ作成の自動化

#### 1. 外部キー関係の自動解決
- `createBookWithAuthor()` - 書籍と執筆者の関連自動作成
- `createSubmissionWithDependencies()` - 入稿に必要な全関連データ自動作成
- `createCircleWithMembers()` - サークルとメンバー関係自動作成

#### 2. 複合パターンの実装
- 多対多関係の簡素化
- CASCADE削除テスト用データ
- バッチ作成機能

### Phase 3: 既存テストファイルのリファクタリング

#### 1. 段階的移行戦略
- 最も重複の多い書籍関連から開始
- 各ファイルでbefore/after比較検証
- 統合テスト実行で品質保証

#### 2. コード削減目標
- 約260行の重複コード削除
- 各テストファイルの簡素化（平均50%削減）
- beforeEach内のデータ作成コード80%削減

### Phase 4: 高度機能追加

#### 1. 動的テストデータ生成
- ランダム値生成（faker.js風）
- パラメータ化テストデータ
- エッジケース自動生成

#### 2. テストシナリオテンプレート
- 標準的なCRUDテスト用データセット
- バリデーションテスト用不正データ
- パフォーマンステスト用大量データ

## 📈 期待される効果

- **保守性向上**: 1箇所修正で全テスト対応
- **コード品質**: 260行削減、可読性大幅向上
- **開発効率**: 新しいテスト作成時間50%削減
- **バリエーション**: 動的・多様なテストデータ生成
- **型安全性**: TypeScript型推論活用による品質向上

## ⚡ 実装優先度

| 優先度 | 実装内容 |
|--------|----------|
| **高** | 重複コード削減、関連データ自動化 |
| **中** | 動的生成、エッジケース対応 |
| **低** | パフォーマンステスト、大量データ生成 |

**重要**: 現在の統合テスト275件全通過を維持しながら、段階的リファクタリングで品質向上を実現します。
