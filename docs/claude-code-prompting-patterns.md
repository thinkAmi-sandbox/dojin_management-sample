## 基本原則

### ✅ 効果的プロンプトの必須要素

1. **明確な作業指示** - 具体的で測定可能な指示
2. **成功基準** - ✅/❌で判定可能な基準
3. **並行実行指示** - Tool callsの効率的活用
4. **期待する成果物** - 具体的なdeliverable
5. **品質保証手順** - テスト・確認方法の明記

### 🚀 効率化テクニック

1. **段階的実行** - リスク最小化のためのPhase分割
2. **並行処理活用** - 複数Tool calls同時実行
3. **文書中心管理** - 進捗の可視化と状況把握
4. **パターン化** - 再利用可能な手順の確立
5. **エラー対応戦略** - 事前定義された対処法

## プロンプトパターン

### 1. 初期計画プロンプト

**用途**: 大規模リファクタリングプロジェクトの包括的計画策定

```markdown
大規模リファクタリングプロジェクト「[プロジェクト名]」を開始します。

【作業要求】
1. [既存計画文書] を読み込み、現状を把握
2. 以下の観点で詳細実装計画を策定：
   - Phase分割（リスク最小化のため段階的実行）
   - 並行実行可能な作業の特定
   - 各Phaseの成功基準・テスト戦略
   - エラー対応パターンの事前定義
   - ロールバック戦略

【期待する成果物】
- 更新された計画文書（進捗管理表、リスク対策込み）
- 次の3つのPhaseの具体的作業手順
- 品質保証のためのテストチェックリスト

【制約条件】
- [重要な品質基準]を維持
- 1つのPhaseで影響範囲は最大[N]コンポーネントまで
- 各Phase完了時点で必ず動作確認実施
```

### 2. 実装プロンプト

**用途**: 明確な成功基準付きの具体的実装作業

```markdown
[プロジェクト名] Phase [N]-[M]「[Phase名]」を実装開始します。

【具体的作業指示】
1. [具体的作業1]
2. [具体的作業2]
3. [具体的作業3]

【成功基準】
- ✅ [測定可能な基準1]
- ✅ [測定可能な基準2]  
- ✅ [測定可能な基準3]
- ✅ [測定可能な基準4]

【並行実行】
- [並行実行可能な作業の組み合わせ]
- [効率化のための同時作業]

【確認手順】
1. [テストコマンド]で[対象]テスト確認
2. 手動で[重要な機能]の動作確認
3. [進捗管理文書]への進捗反映

完了時に「Phase [N]-[M]完了報告」として結果をまとめてください。
```

### 3. 品質確認プロンプト

**用途**: 標準化された品質チェック

```markdown
Phase [N]-[M]完了後の品質確認を実行してください。

【並行実行チェックリスト】
以下を同時に実行して効率化を図る：

1. **テスト実行**（Bash tool使用）
   - `[テストコマンド1]`
   - `[テストコマンド2]`
   - `[テストコマンド3]`

2. **コード品質チェック**（Read tool使用）
   - [チェック対象1]の[チェック項目]確認
   - [チェック対象2]の[チェック項目]確認
   - [チェック対象3]の[チェック項目]確認

3. **機能動作確認**（計画文書参照）
   - [重要機能1]の動作確認
   - [重要機能2]の動作確認
   - [品質特性]保持確認

【報告形式】
- ✅/❌ で明確な判定
- 問題発見時は具体的な修正提案
- 次Phaseへの影響分析
- [進捗管理文書]への反映
```

### 4. エラー対応プロンプト

**用途**: パターン化された体系的エラー対応

```markdown
[エラー種別]が発生しました。体系的なエラー対応を実行してください。

【段階的エラー分析手順】
1. **エラー分類**
   - [パターン1]エラー → [対応方針1]
   - [パターン2]エラー → [対応方針2]
   - [パターン3]エラー → [対応方針3]
   - [パターン4]エラー → [対応方針4]

2. **並行調査実行**
   - [調査対象1]の詳細確認
   - [調査対象2]の関連箇所確認
   - [調査対象3]のログ・状態確認

3. **修正戦略決定**
   - 影響範囲の特定（最小限の修正で解決）
   - 他機能への副作用確認
   - ロールバック要否の判断

【エラー対応完了基準】
- [具体的解決基準1]
- [具体的解決基準2]
- 修正内容の文書化
- 再発防止策の策定
```

   - [対象3] [N]ファイル
   各グループを独立して修正可能

2. **[検証作業]並行実行**（[Tool名]活用）
   - 各[作業単位]修正後に即座に[検証方法]実行
   - 失敗発生時は即座に該当グループのみ修正

## 注意事項

1. **プロンプトのカスタマイズ**: プロジェクトの性質に応じて[プレースホルダー]を適切に置き換えてください
2. **段階的実行**: 大規模作業は必ずPhase分割して実行してください
3. **品質保証**: 各段階でテスト実行と品質確認を必ず実施してください
4. **文書管理**: 進捗と成果を適切に文書化してください
5. **エラー対応**: 問題発生時は体系的なアプローチで対応してください
